# hued

Declarative per-directory terminal colors. A shell hook (`_hued_apply`, wired
via `precmd_functions` in zsh / `PROMPT_COMMAND` in bash / `conf.d` in fish)
walks up from `$PWD` to find the nearest `.hued` file and emits OSC 10/11
escapes to set foreground/background. `HUED_BACKGROUND` / `HUED_FOREGROUND` env
vars override the file (lets direnv/mise drive colors).

The `hued` CLI handles get/set/mod/pack/unpack/resolve/map/pick. Color resolution
shells out to `pastel` for transforms; named colors (CSS + xkcd, generated by
`scripts/generate-names.py`) come from `hued-names.sh` and, for Python,
`src/huedmap/names.py`.

`hued map` (also `-i`) serves a one-off local page for picking a directory's
colors: background, foreground and the three accents, with every background
already in use plotted. `hued pick` is the same page with no target directory;
it prints the pick instead of writing it. It lives in `src/huedmap/`,
stdlib-only Python, and also holds the `.hued` scanner that `pack` and `unpack`
call. All of its color math is in Python; `page.html` only draws what the
server sends. `bin/hued-py` launches it.

To look at the page without opening a browser, run
`node scripts/map-shot/shoot.mjs`: it drives the page in headless Chrome and
writes a screenshot of each state to `out/map-shot/`, emptied on every run.

Distribution: Homebrew tap (`orochi235/hued`) plus manual install. Must stay
**platform-agnostic**.

The formula names each file it installs. A new script in `bin/` or package in
`src/` needs its own line there in the release that ships it, or the installed
copy breaks.

Tests live in `test/` (bats) and `tests/` (pytest). Run with `make` or
the individual `bats test/*.bats` / `pytest` invocations.
